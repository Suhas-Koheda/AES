# Research report — Rubric-conditioned AES on ASAP 2.0

**Status:** protocol, implementation and test suite complete. Full neural
training has **not** been run in this repository's development environment
(CPU-only, no GPU). This report therefore documents the methodology, the
verified dataset properties, the exact analyses the code produces, and the
limitations. It contains **no fabricated results**; every table below is
generated by the listed command once training has run.

---

## Abstract

We test whether conditioning a pretrained Transformer's essay representation
on the writing prompt and the official scoring rubric improves holistic essay
scoring and generalization to unseen prompts. We implement a TF-IDF reference,
a concatenation baseline, a cross-attention model with a gated residual, and
two ordinal-aware objectives, and evaluate them on ASAP 2.0 under two
independent protocols (official benchmark; held-out prompt). The central
empirical question is whether any gain survives a **matched token budget**
comparison, which separates "more context" from "better fusion".

---

## 1. Hypothesis and falsification criteria

* **H1a (rubric effect).** Adding rubric text to the input improves QWK over
  question+answer and essay-only baselines.
* **H1b (fusion effect).** Cross-attention outperforms concatenation at an
  equal token budget.
* **H1c (ordinal effect).** A CORAL or CE+expected-score objective improves
  QWK/MAE over plain 6-way cross-entropy.

Each is falsifiable. If the matched-budget comparison shows no difference,
H1b is rejected and the honest conclusion is that the fusion mechanism is not
what matters. Reported differences smaller than the seed-to-seed standard
deviation will be treated as inconclusive.

---

## 2. Data

Official ASAP 2.0: 17,307 training essays over 7 prompts; 7,421 test essays
over 5 prompts; one shared holistic 1–6 rubric; no trait labels. Two prompts
(`Car-free cities`, `Does the electoral college work?`) appear only in
training. Scores are heavily imbalanced (score 6 ≈ 0.9% of training data).
Full verification is in [`DATASET.md`](DATASET.md).

### Splits

| Protocol | Train | Validation | Test |
|---|---|---|---|
| Official benchmark | 85% of official train | 15% of official train (stratified on prompt × score) | official test (7,421) |
| Held-out prompt | 85% of remaining 6 prompts | 15% of remaining prompts | the held-out prompt |

The official test file is never used for model selection, prompt construction
or rubric refinement. Split manifests (`split_manifest.csv`) make every split
auditable.

## 3. Methods

### 3.1 Input construction

* `question` = the prompt's `assignment` text (one unique text per prompt).
* `rubric` = the official holistic rubric, extracted from
  `asap_scoring_rubric.docx` and parsed into six bands.
* `answer` = `full_text`.
* `target_score` = `score`; class = `score - 1`.

Question+rubric and answer are tokenised under **separate budgets**, so a long
essay cannot truncate the rubric to nothing. Default truncation is
`head_tail`, preserving introduction and conclusion; truncation rates are
measured by `scripts/inspect_dataset.py`.

### 3.2 Models

* **A. TF-IDF + logistic regression.** Word 1–2 grams, 100k features,
  sublinear TF, balanced class weights, `C` selected on validation QWK.
* **B. Transformer baseline.** `microsoft/deberta-v3-small` (configurable to
  `-base`) over `[QUESTION] q [RUBRIC] r [ANSWER] a`; masked attention pooling;
  6-way head.
* **C. Cross-attention.** Shared encoder, separate passes for answer and
  question+rubric, multi-head cross-attention (Q=answer, K=V=context), gated
  residual, masked pooling, dropout, 6-way head.
* **D1. CORAL.** Same encoder as C with 5 ordered logits and the extended
  binary target `1[score > k]`.
* **D2. CE + expected score.** `CE + λ · SmoothL1(E[score], score)` on genuine
  softmax probabilities.

### 3.3 Decoding (kept distinct and tested)

| Head | Logits | Decode | Output |
|---|---|---|---|
| softmax | 6 | `argmax(softmax)` or `round(E[score])` | class 0–5 → score 1–6 |
| CORAL | 5 | `sum_k 1[logit_k > 0]` | class 0–5 → score 1–6 |

Raw regression outputs, expected scores, softmax classes and probability
indices are separate variables throughout (`src/labels.py`).

## 4. Metrics

Primary: **Quadratic Weighted Kappa** on the 1–6 scale. Secondary: MAE, RMSE,
accuracy, Spearman ρ, per-prompt QWK/MAE, confusion matrix, human vs predicted
distributions, parameter count, training/inference time. QWK is computed with a
self-contained implementation cross-checked against
`sklearn.metrics.cohen_kappa_score` in `tests/test_metrics.py`. Undefined
metrics (e.g. constant predictions) return `nan` rather than 0.

Multi-seed runs report mean ± std via
`python scripts/run_from_config.py --config ... --seeds 42 43 44`.

```bash
python scripts/run_ablation.py
python scripts/make_report.py --ablation
```

| # | Row | Config | Isolates |
|---|---|---|---|
| 1 | Essay only | `essay_only.yaml` | value of context at all |
| 2 | Question + answer | `qa_concat.yaml` | value of the question |
| 3 | Question + rubric + answer, concat | `qra_concat.yaml` | value of the rubric |
| 4 | Question + rubric + answer, cross-attention | `qra_cross.yaml` | fusion mechanism |
| 5 | Cross-attention + CORAL | `qra_cross_coral.yaml` | ordinal objective |
| 6 | Cross-attention, matched budget | `cross_attention_matched.yaml` | fusion at equal tokens |

Rows 3 and 6 are the key pair: same 192-token context and 317-token answer
budget, different fusion. Row 4 uses a larger budget (768/512) and is reported
as a separate, non-matched row.

**Confound to report explicitly:** concatenation at 512 total tokens
truncates the rubric to 192 tokens, whereas cross-attention encodes it
separately. `transformer_long.yaml` (1024 tokens) and the matched-budget row
exist to quantify this.

## 7. Fairness and error analysis

Demographics are analysis-only. `src/fairness.py` reports, per category of
`ell_status`, `grade_level`, `gender`, `race_ethnicity`,
`economically_disadvantaged`, `student_disability_status`:

* n, QWK, MAE, RMSE, accuracy, Spearman ρ;
* human and predicted score distributions;
* `small_sample` (< 30) and `qwk_interpretable` (< 50) flags;
* missing-value counts.

It also saves the 50 largest over- and under-scores
(`fairness/largest_over_scores.csv`, `largest_under_scores.csv`) and per-prompt
metrics. No causal language is used; missing demographics are never imputed.

Known missingness in training: 4,019 rows lack economic/disability status; 240
lack ELL status; 19 lack race/ethnicity.

## 8. Threats to validity

1. **Train/test prompt mismatch.** Two prompts are train-only. Per-prompt
   results are not exchangeable.
2. **Public/private test composition.** 2,257 public vs 5,164 private; a
   distribution shift between them would affect aggregate test QWK.
3. **Validation carve-out.** No official validation split exists; results
   depend on the seeded stratified split. Multi-seed runs mitigate this.
4. **Class imbalance.** Argmax models may rarely predict score 6; QWK is
   sensitive to the confusion structure.
5. **Long-context extrapolation.** `transformer_long.yaml` runs DeBERTa beyond
   its nominal 512-token pretraining length; this is an extrapolation.
6. **Single dataset.** ASAP 2.0 is source-based persuasive writing; results
   may not transfer to other genres or rubrics.

---

## 9. Limitations

* No criterion-level or trait-level supervision; only holistic 1–6 scores.
* No cross-rubric generalization (one rubric only).
* Source-text conditioning feasible for only 2 of 7 prompts without OCR.
* Full-scale multi-seed training is compute-intensive; the provided defaults
  (`deberta-v3-small`, 4 epochs, batch 16, fp16) target a single 16 GB GPU.

## 10. Next steps

1. Run the full matrix with ≥3 seeds on a GPU; report paired tests across
   prompts rather than only mean QWK.
2. Inspect cross-attention weights: do they concentrate on rubric bands near
   the predicted score, or on the question's task verbs?
3. Add a frozen-encoder condition to separate "context access" from
   "representation learning".
4. Extend to chunked long-input encoding and compare with head/tail
   truncation at equal token counts.
5. If a multi-rubric corpus becomes available, run the cross-rubric protocol
   from Kumar et al. (2026) with the same code.
